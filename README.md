# Multi-Entity Consolidation & Board Reporting Platform

**Northstar Industrial Group** — a $412m, twelve-entity, five-country industrial group running
three ERP systems in four currencies, consolidating monthly in a spreadsheet.

This repository builds the platform that replaces that spreadsheet: a reproducible
consolidation engine, an automated control framework, an Excel FP&A suite, a Power BI
executive reporting suite and a board reporting pack — with a traceable path from every board
figure back to the source journal that produced it.

> **Northstar Industrial Group is fictional.** All data is synthetic, deterministic and
> generated by this repository. The company, its entities and its financials are constructed
> to be realistic, internally consistent and non-trivial.

## The engagement in one page

**The problem.** Northstar grew from one business to twelve legal entities in seven years,
almost entirely by acquisition, and finance was never rebuilt to match. Month-end takes four
days in a spreadsheet. Three ERPs, three charts of accounts, three sign conventions. FX is
translated manually at annual average rates with CTA plugged to balance. Intercompany is
reconciled by email. The cash flow statement is hand-built and breaks whenever the balance
sheet changes.

As the CFO put it: *"The numbers are probably right. I cannot prove they are right, and I
cannot show the board where they came from."*

**The approach.** Anchor-first. The group's financial anchors are defined and proven *before*
any transaction is generated, as an executable model that verifies its own accounting
identities. Synthetic data is then generated to hit those anchors and tested back against
them. Entities, mappings, FX policy, intercompany relationships and controls are all
version-controlled configuration validated in CI — not code, and not tribal knowledge.

**What makes it defensible.** Every transformation between the source trial balance and the
board number is a separately identifiable layer, so the reconciliation from "what the ERPs
said" to "what the board sees" is a standing output rather than an investigation. 71 automated
controls, 56 of them blocking, run at the point of the transformation they protect.

## Quick start

```bash
git clone <repository>
cd northstar-consolidation-platform

python -m pip install -r requirements.txt

python src/anchors/build_anchors.py    # rebuild the financial anchors and their documentation
python -m pytest tests -q              # validate every accounting identity and config seed
```

Expected output:

```
All integrity assertions passed (BS balances; CF ties to BS cash).
152 passed
```

## Design principles

1. **Financial correctness first.** A beautiful chart of a number that does not tie is worse
   than useless, because it is believed.
2. **Nothing is netted before it is understood.** Every step from source to board number is a
   separately reportable layer.
3. **Configuration over code.** A controller can change a mapping through a pull request.
4. **Controls block.** A failed blocking control stops the pipeline. It does not produce a
   warning that gets ignored for six months.
5. **Deterministic and reproducible.** Same inputs, same outputs, byte for byte. No manual
   spreadsheet step in the critical path.
6. **Anchors before data.** If generated data disagrees with the anchors, the generators are
   wrong.
